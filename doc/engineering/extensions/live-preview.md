# 浏览器实时预览扩展

2026-10-27。课程基线 `final` / `1d6b3fd` 保持不变；扩展分支 `feat/live-preview`。

## 目标与验收（REQ-15）

- `npm run preview`（等价 `npm run cli -- --preview`）启动 CLI 和本机浏览器预览服务，终端输出可打开的地址。
- 无文档时提示 init/read；成功 init/read、编辑、undo/redo、canvas 修改后无需 save 即自动显示内存中的 SVG。
- 页面每 300ms 串行检查文档版本，未改变时不重复序列化或传输 SVG；这是轮询间隔，不是延迟 SLA。
- 查询、失败命令及预览请求不得改变文档、绑定路径和历史；save 保留原有屏障语义。
- 支持多个页面、断线提示与自动重试；CLI 退出时关闭服务。
- 服务仅绑定 127.0.0.1 随机空闲端口，随机会话路径；只读接口，不暴露目录或执行命令。SVG 作为 img 图片显示。
- 原 CLI 默认行为兼容，无新增运行时依赖。

## 方案选择与工作拆分

1. 本地提交需求、ADR 和验收计划。
2. 应用会话提供只读文档版本；HTTP 适配器按版本读取副本并复用 SvgCodec，bootstrap 装配。浏览器页面显示画布、连接状态及适应窗口/原尺寸选项。
3. 自动回归：文档变化/失败原子性、历史/路径保护、HTTP 边界、并发页面、退出清理、真实 CLI 启动。真实浏览器检查实际画面与自动刷新。
4. 完成 npm run check、Node 22/24 干净检出验证与实际自查，更新证据并集中推送功能分支。不移动 final，不自动合并 main。

比较：桌面 GUI 需要额外框架和分发；文件监听必须先落盘且混淆 save 语义；WebSocket/SSE 对单进程只读预览增加连接生命周期复杂度。选择浏览器 + 短轮询，无业务层 IO、无持久连接。仅在版本改变时序列化完整快照，超大文档成本与现有快照模型相同，暂不做增量渲染。

## 自查与限制

- 自查实际 diff：领域层无修改，应用层仅增加版本状态；HTTP/浏览器全部在适配层；没有新增业务命令分派。架构自动检查通过。
- 预览从副本编码，无文件读取/写入接口；失败渲染不反向使已提交命令失败。原始附件未改，课程 main/final 未移动。
- 未安装新依赖，未进行独立人工评审。浏览器实际验收覆盖本机 Chrome；未声称 Safari、Firefox、Linux 或多人远程访问已验证。
- 300ms 是串行轮询间隔，不保证端到端延迟；后台标签可能被浏览器限速。大文档仍按版本复制/序列化完整 SVG。
- 浏览器只读，需在终端编辑；预览不保存文件。CLI 重启生成新 URL，旧页面不能连接新会话，需打开新链接。
